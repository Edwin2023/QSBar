# QSBar 仓库更新与版本发布指南

本指南旨在规范 QSBar 插件的版本管理、更新文件托管及自动更新发布流程。

## 1. 核心原理
QSBar 的自动更新功能本质上是利用 **Gitee 的 Raw 文件下载服务** 作为静态文件服务器。
- **伪装请求**：通过在代码中加入 `User-Agent` 请求头，模拟浏览器访问，绕过 Gitee 的基础防爬虫机制。
- **静默更新**：主要通过替换 `QSBar.dll` 实现逻辑更新，无需用户重新运行安装程序。

## 2. 版本发布流程 (Step-by-Step)

### 第一步：修改代码中的版本号
在发布新版本前，需确保以下三处的版本号一致：
1. **项目版本**：在 VS 中修改 `QSBar` 项目属性 -> 应用程序 -> 程序集信息中的版本号（对应 [QSBar.csproj](file:///e:/Code/QSBar/QSBar/QSBar.csproj)）。
2. **安装包版本**：修改 [QSBar_Installer.iss](file:///e:/Code/QSBar/QSBar_Installer.iss) 中的 `AppVersion`。
3. **更新描述**：修改 [version.json](file:///e:/Code/QSBar/version.json) 中的 `latestVersion`。

### 第二步：编译与打包
1. 在 Visual Studio 中以 `Release` 模式重新生成解决方案。
2. 运行 Inno Setup 编译器，加载 [QSBar_Installer.iss](file:///e:/Code/QSBar/QSBar_Installer.iss)，生成最新的 `QSBar_Setup.exe`。

### 第三步：上传更新文件到 Gitee
推荐使用 Gitee 的 **Release (发布)** 功能，因为其链接更稳定且易于管理。

1. **创建标签 (Tag)**：
   ```bash
   git tag -a v1.0.x -m "版本说明"
   git push origin v1.0.x
   ```
2. **创建发布 (Release)**：
   - 进入 Gitee 仓库页面 -> 右侧 "发布" -> "创建发布"。
   - 选择刚创建的 Tag。
   - **重要**：将 `bin/Release/QSBar.dll` 和生成的 `QSBar_Setup.exe` 上传为附件。

### 第四步：获取直链并更新 version.json
1. 在 Gitee Release 页面，右键点击附件中的 `QSBar.dll`，选择“复制链接地址”。
2. 将该链接填入 [version.json](file:///e:/Code/QSBar/version.json) 的 `downloadUrl` 字段。
3. 更新 `changelog` 描述本次更新的内容。
4. 提交并推送 [version.json](file:///e:/Code/QSBar/version.json) 到仓库。

## 3. Gitee Raw 链接格式参考
如果你不使用 Release 附件，也可以直接引用仓库中的文件：
- **格式**：`https://gitee.com/用户名/仓库名/raw/分支名/文件路径`
- **示例**：`https://gitee.com/kevin137/qsbar/raw/master/version.json`

## 4. 注意事项
- **DLL 锁定**：自动更新时会尝试结束 Excel/WPS 进程以解除 DLL 占用。如果更新失败，请提醒用户手动关闭所有 Office 窗口。
- **安全性**：由于 Gitee 是公开仓库，请勿在 [version.json](file:///e:/Code/QSBar/version.json) 或代码中存放任何敏感信息。
- **回退机制**：若新版有 Bug，只需将 [version.json](file:///e:/Code/QSBar/version.json) 中的 `latestVersion` 改回旧版本号，并将 `downloadUrl` 指向旧版的 DLL 链接即可实现全员降级。
